GitHub Issues Sync: loading only what changed

My third project pulls issues from the dbt-core repository through the GitHub API into BigQuery every day. The goal was an incremental load: each run asks BigQuery for the newest update it already has and fetches only newer issues. Raw rows are appended, then a window function keeps the latest version of each issue.

One detail I liked: GitHub's since filter is inclusive, so every run re-fetches a few issues it already has. During testing, one issue was captured only because of that overlap. A strict cursor would have skipped it for good, and the dedupe step handles the repeats.

EIA Electricity Price Pipeline: my first full git workflow

This one starts from an API instead of a file. Python loads U.S. retail electricity prices from the EIA into BigQuery, and dbt cleans them and builds a year-over-year price table using a LAG window function. It runs on a schedule, with tests on the key columns.

I created the repo and made each commit myself in WSL, which meant learning the loop of edit, check, commit, and push. I also built the Power BI version of the dashboard by hand from a CSV export of the final table, next to the Tableau version.

Turning an analysis into a pipeline

My first portfolio project was a one-off SQL analysis. I rebuilt it as a repeatable pipeline: Python ingest, dbt models in staging, intermediate, and mart layers, about 25 data tests, and GitHub Actions. Claude wrote most of the code, and the README says so. My part was running it and checking the results. It reproduced my original numbers exactly, down to the same 1,089 reliable baselines.

I then rebuilt the Tableau dashboard in Power BI Desktop, to compare how the two tools handle the same data.

Oct 20, 2026

Building Electricity Baseline Screening

I wanted a portfolio project that uses no work data. I used the public Building Data Genome 2 dataset: 25 million hourly readings across about 1,600 buildings. I built per-building baselines in BigQuery SQL, then added a data-quality check. It flagged 362 buildings for meter problems and kept 1,089 reliable ones.

The dashboard runs on exported CSVs, because BigQuery sandbox tables expire.
