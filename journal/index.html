AI Data Center Scaling Planner: From Training Run to Power and Cost

This notebook takes a planned AI training run, measured in FLOP, and works out what a data center planner has to line up: the number of accelerators, IT and facility megawatts, energy use, and capital cost. It then lays those out year by year against the power available, which shows when to file for grid interconnection and when to start construction.

The method follows the Kaplan and Chinchilla scaling-law papers. Hardware, facility, and price defaults come from published sources and are cited in the notebook. A validation section re-derives figures the papers report directly and fails loudly if a change breaks the math.

It is a planning calculator, not a forecast. The default run sizes extrapolate a historical trend, and the notebook says so. I designed the calculations and checked the results, using AI tools to generate the code.

GitHub Issues Sync: An Incremental API-to-BigQuery Load

This pipeline syncs issues from the public dbt-core repository into BigQuery every day. Each run reads the newest update already loaded and requests only issues changed since then. Raw rows are appended, and a window function keeps the latest version of each issue for the clean table and the dbt monthly summary. Retries with backoff, rate-limit handling, and logging cover the API calls.

GitHub's since filter is inclusive, so every run re-fetches a few issues it has already loaded. During testing, one issue was captured only because of that overlap. A strict cursor would have missed it permanently, and the deduplication step absorbs the repeats safely.

EIA Electricity Price Pipeline: API to Dashboard

This project loads U.S. retail electricity prices from the EIA API into BigQuery with Python on a schedule. dbt cleans the data in a staging layer and builds a year-over-year price table with a LAG window function, with tests on the key columns. Dashboards in Tableau Public and Power BI read from the final table.

It was also my first project managed entirely through a git workflow: a new repository, small commits, and each change reviewed before it was pushed.

October 20, 2026

Building Electricity Baseline Screening: The Analysis

The first version estimated expected electricity use for each building from hour of day, weekday or weekend, and temperature. It used 25 million hourly readings from about 1,600 buildings in the public Building Data Genome 2 dataset, with the baselines built in BigQuery SQL. A data-quality check then flagged 362 buildings for meter issues and kept 1,089 reliable baselines for screening.

The Tableau Public dashboard is built on exported CSV files, so it stays available after the temporary BigQuery tables expire.
